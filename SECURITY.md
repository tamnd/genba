# Security policy

## Reporting a vulnerability

Please report vulnerabilities privately through [GitHub Security Advisories](https://github.com/tamnd/genba/security/advisories/new).
Do not open a public issue for a security problem.

Include what you found, how to reproduce it, and what an attacker gets out of it.
A proof of concept helps a lot.
You will get an acknowledgement within three working days and an assessment within seven.

## Supported versions

The latest tagged release is the supported one.
Fixes are released as a new patch version rather than backported.

## What counts as a vulnerability here

The project exists to put a permission boundary around a company's documents, so anything that crosses that boundary is a vulnerability even if it looks small:

- A path that returns a document to a principal whose permissions do not allow it, including through a cache, a snippet, a facet count, an error message or a timing difference.
- A path that returns document content without a principal at all.
- A document whose permissions failed to resolve becoming visible to anybody.
- A response that lets a caller distinguish a forbidden document from a missing one.
- Anything that leaks an internal group name, an access control list or another tenant's data to a client.
- The usual classes: injection into a storage driver, authentication bypass, request forgery, deserialisation of untrusted input, and dependency vulnerabilities that are reachable from this code.

## What does not

- `api.HeaderAuth` trusts the headers it reads.
  That is documented on the type.
  It is for local development and for deployments behind a proxy that has already authenticated the caller and strips those headers from outside traffic.
  Exposing it directly to an untrusted network is a configuration mistake rather than a vulnerability.
- Reports generated by a scanner with no analysis of whether the finding is reachable.

## Release integrity

Release checksums are signed with cosign using keyless signing, and every archive ships an SBOM.
Container images are signed the same way.
To verify a download:

```
cosign verify-blob checksums.txt \
  --certificate checksums.txt.pem \
  --signature checksums.txt.sig \
  --certificate-identity-regexp 'https://github.com/tamnd/genba/.*' \
  --certificate-oidc-issuer https://token.actions.githubusercontent.com
```
